### [Discuss handling crates not taking web compatibility fixes](https://servo.zulipchat.com/#narrow/channel/500774-tsc/topic/Discuss.20handling.20crates.20not.20taking.20web.20compatibility.20fixes/with/631567939)

rego: Tim started a discussion about this in relation to a particular crate not taking our patches / not doing new releases. What should we do in these cases?

jonathan: Aside from Tim's problem, we have a similar one with freetype-sys. In Tim's case the maintainer doesn't want the patch. In my case the maintainer is not active. Ideally you fix these issues upstream, but if the maintainer doesn't want to respond then forking is on the table. In my opinion we should try to see how much workload that puts on us. In Tim's case that was the http or hyper crate. That sounds like it would add a lot of maintenance burden to us, because we'd have to fork a bunch of crates. Seems quite involved. I'm a bit worried that it adds a lot of work for us if we go with the forking route. For an unmaintained crate it makes more sense, because rebasing is only once a year. Active crate is a very different situation.

martin: For the more complicated crates, like hyper, are there people we can talk to? This is the kind of case where having connections is helpful, maybe get in a call with someone, or maybe make a blog post without causing too much drama, but expressing why we need these things, maybe we can use that to help to improve things

martin: for the freetype crate, we used to have our own freetype crate, we could do it again, if we do it, probably we should ensure WebRender upstream uses our crate also; don't remember the exact issue with freetype

jonathan: Regarding freetype it was one PR which exposes new functions in Freetype (not that new anymore), but the bindings haven't been used in a while. Now we are carrying this in a downstream fork of Servo...have to get things working somehow. There's also the issue that it bundles a bunch of crates such as libpng -- it's a C library so there are vulnerabilities there. I did ask an agent and it said there are no known exploits...but it would feel better if we could keep the libpng updated upstream. For httpparse / hyper the person to talk to would be sean. We could organize a call or do something.

jonathan: Yeah, seanmonster who was commenting on Tim's PR.

jonathan: We could just put the extern C functions in Servo.

martin: I think we had done that before even.
